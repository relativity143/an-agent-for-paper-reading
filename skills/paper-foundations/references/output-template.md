# 每轮输出与记录

按当前阅读阶段使用下面的导读、逐句讲解、完整讲解或走进领域模板；内容跟随读者使用的语言。明确问论文位置或下一篇时直接使用对应模板，不要求先完成导读、卡点或完整讲解。无需为背景登记、错误说明或位置确认硬凑讲解。原句很长时只展示足以定位的片段，并标明省略。来源放在相关解释旁，不另堆一份无法对应主张的书单。

## 全文导读

首次阅读当前论文版本、日志尚无 `type: "overview"` 时输出；用 `log show <paper> --type overview --last 1` 检查，先筛选类型再取最后一条，不能凭未筛选的近期记录判断。读者之后明确要求时可以再给一次。基于已通读的正文和 `outline.md`，对照读者背景，控制在一屏以内：

```text
【全文导读】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
1. 这篇论文在问什么：<一两句，用读者能懂的话>（<位置>）
2. 核心模型 / 实验：
   - 研究对象：……（<式或节>）
   - 调节的参数：……（<位置>）
   - 测量或计算的量：……（<式或图>）
3. 主要结论（作者报告，注明适用范围）：……（<节或图>）
4. 整篇依赖的基础（对照你的背景，可能需要补的）：
   - <基础>：一两句最基础的认识（<论文用到它的位置；背景来源>）
   - ……（2 到 4 项，每项都可以单独展开）
   已在前几篇补过的：<基础>（《<论文>》，你确认懂了／讲过）；……
5. 阅读路线：主线是 <节和图的顺序>；第一遍可以略读 <节>。
6. 接下来：建议从 <位置> 开始读；哪句卡住就贴给我。
```

第 2 项按论文类型取舍：理论论文讲对象、哈密顿量或方程、参数；实验论文讲样品、装置、调节的量和测量的量；数值论文讲模型、数值方法和计算的量。各项都给原文定位，作者主张与背景知识分开，保留结论适用范围；导读是阅读地图，不替代全文，也不把不明确的背景缺口写成事实。

导读前用 `profile concepts --exclude-paper <当前论文>` 对照已有基础；同一 arXiv 编号的其他版本也属于当前论文，不充作跨篇来源。`known` 写“你确认懂了”，`explained` 仅写“讲过”，`unsure` 仍列入需要补的。只引用实际记录的论文和位置；没有其他论文来源时省略“已在前几篇补过的”一行，无 `paper` 来源的概念只能用于判断背景。核对概念的含义、定义和条件后才沿用，不能把相似名称当成同一知识；尤其非厄米 chiral symmetry 与 sublattice symmetry 须逐一核对定义，拿不准就标为待补或待核实。

读者一开始就带着具体卡住的句子时，只把第 1 到 3 项压缩为三到五行简版导读，随后进入下面的逐句讲解。完整和简版导读都在实际输出后单独记录为 `overview`。之后的逐句讲解沿用这里建立的图景，不重复导读；“放回全文”以这条主线为参照。全文尚未读到时，说明限制，不编造导读或提前记录已完成。

## 逐句讲解

按以下顺序组织，保留各项：

```text
【卡住的位置】§<节标题>（<句子编号>）：“<原句或明确省略的片段>”
【这句默认你知道】<必要的知识缺口>（<依据；不确定时标为暂定判断>）
【基础讲解】
1. <基础概念>：只讲这里用到的一面，给必要条件及背景来源。
2. <需要时的第二个概念>：……
3. <需要时的第三个概念>：……
合起来：<这些基础怎样组成原句的含义>。
【回到这句话】“<原词>”在这里指……；“<符号/公式/图>”在这里表达……。
【放回全文】这一段在 <节> 中负责……；前文 <位置> 已经……；
后文 <核实的位置> 还会用到“<概念>”，用于……。
【接着读】从 <下一段编号> 开始，留意 <与当前卡点直接相关的一点>。
（讲解中用到但没展开的词：<列表；没有则写“无”>。不熟就说一声。）
```

只使用实际需要的概念项。若尚未找到后文出现的位置，在“放回全文”中写明未查到；没有下一段时说明已到正文末尾。概念名及其 LaTeX 符号都要搜，并核对上下文与定义；不要补造编号或把单纯的词或符号命中写成已验证的论证关系。

对于 `pdf_only` / `local_pdf`，把所有编号换为核实过的定位，例如“PDF 第 3 页，第 2 段”；区分 PDF 页序与页面印刷页码。不得伪造 HTML 段落编号。全文或某页尚未读取时明确注明相应限制。

## 完整讲解（第二部分）

读者仅表示读完全文时，最多提议一次，等待同意；读者明确要求完整讲解时直接给目录，不再次征求确认。先给目录，之后每次最多讲一段，讲完等待回应。目录按本文核心内容分 3 到 8 段，不能把目录或邀请记作已完成一段讲解。

```text
【完整讲解·目录】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
范围：<本文核心：理论模型 / 实验 / 数值方法；不展开的部分及原因>
第一部分已讲过的基础：<概念>（<讲过的位置>）；……
分段：
  1. 设定与假设（<原文范围>）
  2. <核心推导或测量流程的一步>（<原文范围>）
  ……
  N. 结论、证据与边界（<原文范围>）
```

每段约一屏，以接近原文的严谨程度解释。理论论文侧重模型、推导和条件；实验论文侧重样品与装置、测量原理、数据处理、误差与对照；数值论文侧重模型、算法、收敛性、有限尺寸效应和统计处理。

```text
【完整讲解·第 k 段】<段标题>（<原文范围>）
<按逻辑顺序讲清本段的设定、推导或测量步骤；定义全部符号、单位及约定，
注明近似和适用条件。省略代数时写明“此处省略……，见式……／附录……”。
区分作者主张、证据支持程度与背景知识，引用对应原文；说明第一部分哪些说法
是简化版本，这里补全了什么。最后一段交代各主要结论的计算、测量或图证据，
作者承认的局限和尚未验证之处。>
【这段用到的基础】<概念>（第一部分在 <位置> 讲过）；……
【读到这里】想接着读就说“继续”；卡在哪里直接说，我会按逐句讲解的方式补上，
再回到这一段。如果这段看懂了或读顺了，也可以直接告诉我。
```

第一部分已讲且档案为 `explained` 或 `known` 的基础可直接使用并标出处，列入本段 `uses`；`explained` 不代表读者已懂，`unsure` 仍需针对卡点补讲。未讲过且不熟的词当场解释；这类词较多时把漏掉的基础记入 `gaps`。PDF 使用已核实的页码范围，不补造 HTML 编号。

段间等待回应；最后一段按下一段说明补充本篇位置后再等待。单说“继续”只推进，不更新 `known`。读者明确说本段看懂或读顺时，才可按确认范围把该段 `uses` 中的概念记为 `known`，`--source` 保存原话；只确认某个概念就只更新那个。卡住时只把明确涉及的概念记为 `unsure`，用逐句模板补讲、记录为 `sentence`，再回到当前段。补讲不自动清除 `unsure`，不自动推进，不宣称读者已掌握。

最后一段实际讲完后，默认接着给下面的“本篇在领域中的位置”，不再用“继续”暗示还有未讲的段落。之后最多提议一次“下一篇读什么”，等读者同意；邀请不算已经给出推荐，也不更新理解状态。

## 本篇在领域中的位置与下一篇读什么

本篇位置默认在第二部分最后一段之后给出，首次导读不展开；读者随时明确问位置时可直接给。用本篇引言、正文中的依赖或对照关系选文献，再用 `ref` 取对应条目与 `doi` / `arxiv_id`，用 `lookup <DOI|arXiv 编号>` 查来源并实际阅读。

```text
【本篇在领域中的位置】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
- 奠基工作：<参考文献编号与简称>——来源大致研究了……；
  本文作者在 <位置> 将它用于／描述为……（核对：摘要／全文，<链接>）
- 直接前作：……
- 对照工作：……
```

通常列本篇直接依赖或对照的 3 到 5 项，按实际角色取舍，不必凑齐所有类别。核实不足时只列已核实项并说明缺口；一项都未核实时只说明限制，不写空的完成记录。作者对前作的描述与来源核对后的事实分开写，例如“本文作者称不同于 [41]”不等于已独立确认该差异。仅核对摘要时只说明工作大致做了什么；具体结论、差异或优先权须核对原文相关部分并给出位置。

第二部分和本篇位置都结束后，结合当前对话和 `log show <paper> --type field --last 5`，最多邀请一次推荐后续阅读，等读者同意。拒绝、沉默和到达末段都不算同意。读者主动问下一篇时直接推荐，不再次征求确认，也不要求先完成本篇位置或第二部分。

```text
【下一篇读什么】
1. <文献>（补基础的讲义或综述）：为什么读……；
   按你的档案还缺：……（暂定；讲过但未确认的……／仍不确定的……）
   （核对：摘要／全文，<链接>）
2. <文献>（奠基论文）：为什么读……；按你的档案还缺：……（暂定）
   （核对：摘要／全文，<链接>）
3. <文献>（相关的新工作）：为什么读……；按你的档案还缺：……（暂定）
   （核对：摘要／全文，<链接>）
```

最多 3 篇，按需要取舍类别和数量；缺少可核实来源时少列，不为凑书单添条目。优先从本篇参考文献中选，使用宿主检索得到的外部候选同样须经 `lookup` 查来源并实际核对。理由限定在读过的内容能支持的范围；缺少的基础是按档案的暂定判断，不把 `explained` 当作 `known`，也不把未知背景当成确定缺口。未发现缺口时可写“档案中暂未发现明确缺口”，记录的 `missing` 可为空数组。

`lookup` 返回标题、作者、年份、摘要、来源服务及链接，缓存命中时可离线复用，用 `--refresh` 才重新请求。查到标题或条目不等于核实科学内容；`abstract: null` 不能标“核对：摘要”，应另行打开来源。服务不可用且无可用缓存、或来源不可读时说明限制，未核实条目不纳入输出或 `field`。`checked` 按实际读过的层次填写，不能因工具成功就自动标为 `abstract` 或 `fulltext`。不扩展为长篇领域综述、文献史或自动引用网络。

## 全文脉络 outline.md

用 `outline-path` 返回的路径保存。用 `text <paper>` 通读，或以 `text <paper> --section <节编号>` 分节读完全文；需要完整结构时仍可读 `paper.json`，PDF 使用宿主阅读能力。通读后写入并按版本复用；它是宿主使用的脉络材料，面向读者的导读还需按背景调整：

```markdown
# <标题>（<arXiv 编号与版本；本地 PDF 则用缓存标识>）

## 论文主线
三到五句：研究问题、方法、主要结论及必要的范围限定。

## 各节作用
- <节编号与标题>：这一节怎样推进论证；引入了哪些当前阅读需要的概念。
```

## 私有讲解记录

每次导读、逐句讲解、完整讲解的一段或走进领域的一个分支各以一个 JSON 对象传给 `log add <paper> --json -` 的标准输入。记录真实内容，不原样运行示例，不把占位文本写进档案。`time` 使用真实时间；若省略，由工具填入。`type` 默认为 `sentence`；旧记录缺少 `type` 时也按逐句记录理解，读取和筛选时不改写旧文件。

`deep` 必须有从 1 开始的正整数 `segment`，不能用布尔值、零、小数或字符串代替。`uses` 为字符串数组，可为空；省略时默认为 `[]`。`sentence`、`overview` 和 `field` 不得带 `segment`，即使值为 `null` 也不允许。`uses` 记录本段直接使用的、第一部分已讲基础；`explained` 只记本次实际补充解释的内容，不能把全部 `uses` 误写成新讲过的基础。

逐句讲解示例：

```json
{
  "type": "sentence",
  "where": "S1.p4.s6",
  "quote": "当前卡住的句子或片段",
  "gaps": ["本轮识别出的缺口"],
  "explained": ["本轮实际讲解的概念"],
  "unexpanded_terms": [],
  "next": "S1.p5",
  "feedback": null
}
```

导读单独记录，`where` 为 `null`；简版只记录实际讲过的内容，不把尚未讲的基础加入 `explained`：

```json
{
  "type": "overview",
  "where": null,
  "quote": "",
  "gaps": ["对照读者背景暂定的基础缺口"],
  "explained": ["导读中实际解释过的模型或基础概念"],
  "unexpanded_terms": [],
  "next": "S1.p1",
  "feedback": null
}
```

反馈另追加一行，`where` 保留其对应位置（导读反馈可为 `null`），`feedback` 保存读者原话；未新增讲解时 `explained` 留空，也不把单纯反馈记为一次新的 `overview`。读者档案使用 `known` / `unsure` / `explained` 状态：只有读者明确确认理解才记为 `known` 并保存原话，细则见 SKILL.md。

完整讲解的一段记录示例（`where` 为该段覆盖的原文范围）：

```json
{
  "type": "deep",
  "segment": 1,
  "where": "S2.SS1–S2.SS2",
  "quote": "",
  "uses": ["哈密顿量", "边界条件"],
  "gaps": [],
  "explained": [],
  "unexpanded_terms": [],
  "next": "S2.SS3",
  "feedback": null
}
```

读者回应另写一行，保留本段 `segment`、`where` 和 `uses`。以下示例是不同反馈分支，不代表实际发生的对话，也不能依次照写进私有日志：

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "explained": [], "next": "S2.SS3", "feedback": "继续"}
```

这条仅请求下一段，不执行 `profile mark ... known`。

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "explained": [], "next": "S2.SS3", "feedback": "这一段读顺了，哈密顿量和边界条件都看懂了"}
```

这条明确覆盖两个 `uses` 概念，可分别 `profile mark` 为 `known`，`--source` 使用该条原话，`--where` 保留当前范围。若原话只确认哈密顿量，就只更新哈密顿量。

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "gaps": ["边界条件"], "explained": [], "next": "S2.SS1–S2.SS2", "feedback": "我还是卡在边界条件这里"}
```

这条只把边界条件记为 `unsure` 并保存原话；定位到实际卡住的句子，按逐句模板补讲后回到第 1 段。反馈行不是新讲解段，不能增加段号；补讲记录也不能代替读者确认。

用 `log show <paper> --type deep --last 5` 查看近期完整讲解及反馈，必要时增加数量。类型筛选在 `--last` 截取前进行；`--last 0` 返回该类型的全部记录。恢复进度时结合实际讲解条目（通常 `feedback: null`）、对应反馈和 `segment` 判断；不要按行数计段，也不要将 `next` 所指的位置当成已讲完的位置。

本篇位置与后续推荐各在实际输出后写一条 `field`，`where` 必须为 `null`，`kind` 为 `position` 或 `next`。`items` 为对象数组，每项包含 `label`、非空的 `title`、`role`、`checked` 和可访问来源的 HTTP(S) `link`；`position` 的 `label` 是非空的本篇参考文献标识，`next` 的 `label` 无本篇编号时可用空字符串或 `null`。角色按分支取值：`position` 为 `foundational` / `predecessor` / `contrast`，`next` 为 `notes` / `foundational` / `recent`。`checked` 仅为 `abstract` / `fulltext`；`next` 每项还须有字符串数组 `missing`，允许为空。记录不包含未核实候选，不使用 `segment`，邀请和服务失败均不记成已完成。

以下只展示格式，标题、编号、链接及缺口须替换为实际核实的内容；一项示例不代表已完成足量核实：

```json
{
  "type": "field",
  "where": null,
  "kind": "position",
  "items": [
    {
      "label": "[26]",
      "title": "<已核实的前作标题>",
      "role": "predecessor",
      "checked": "abstract",
      "link": "https://example.org/verified-source"
    }
  ]
}
```

```json
{
  "type": "field",
  "where": null,
  "kind": "next",
  "items": [
    {
      "label": "",
      "title": "<已核实的讲义或综述标题>",
      "role": "notes",
      "checked": "fulltext",
      "link": "https://example.org/verified-reading",
      "missing": ["<按档案暂定需要补的基础>"]
    }
  ]
}
```

用 `log show <paper> --type field --last 5` 恢复已给出的论文位置和推荐，`--last 0` 仅在需要全部该类型记录时使用。字段记录本身不更新 `known` / `explained` / `unsure`；已给出书单也不意味着读者读过或学会了其中内容。

日志、档案和缓存保留在本机私有数据目录。需要分享到仓库的例子只写论文标识、位置与自己的讲解；论文原文摘录须另核对许可与分享范围，不把私有日志整份复制进去。
