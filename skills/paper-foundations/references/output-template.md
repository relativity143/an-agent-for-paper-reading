# 每轮输出与记录

按以下顺序组织一次讲解，保留各项；内容跟随读者使用的语言。无需为背景登记、错误说明或位置确认硬凑讲解。原句很长时只展示足以定位的片段，并标明省略。来源放在相关解释旁，不另堆一份无法对应主张的书单。

```text
【卡住的位置】§<节标题>（<句子编号>）：“<原句或明确省略的片段>”
【这句默认你知道】<必要的知识缺口>（<依据；不确定时标为暂定判断>）
【基础讲解】
1. <基础概念>：只讲这里用到的一面，给必要条件及背景来源。
2. <需要时的第二个概念>：……
3. <需要时的第三个概念>：……
合起来：<这些基础怎样组成原句的含义>。
【回到这句话】“<原词>”在这里指……；“<符号/公式/图>”在这里表达……。
【放回全文】这一段在 <节> 中负责……；前文 <位置> 已经……；
后文 <核实的位置> 还会用到“<概念>”，用于……。
【接着读】从 <下一段编号> 开始，留意 <与当前卡点直接相关的一点>。
（讲解中用到但没展开的词：<列表；没有则写“无”>。不熟就说一声。）
```

只使用实际需要的概念项。若尚未找到后文出现的位置，在“放回全文”中写明未查到；没有下一段时说明已到正文末尾。不要补造编号或把单纯的词命中写成已验证的论证关系。

对于 `pdf_only` / `local_pdf`，把所有编号换为核实过的定位，例如“PDF 第 3 页，第 2 段”；区分 PDF 页序与页面印刷页码。不得伪造 HTML 段落编号。全文或某页尚未读取时明确注明相应限制。

## 全文脉络 outline.md

用 `outline-path` 返回的路径保存。通读全文后写入并按版本复用：

```markdown
# <标题>（<arXiv 编号与版本；本地 PDF 则用缓存标识>）

## 论文主线
三到五句：研究问题、方法、主要结论及必要的范围限定。

## 各节作用
- <节编号与标题>：这一节怎样推进论证；引入了哪些当前阅读需要的概念。
```

## 私有讲解记录

每轮以一个 JSON 对象传给 `log add <paper> --json -` 的标准输入。记录真实内容，不原样运行示例，不把占位文本写进档案。`time` 使用真实时间；若省略，由工具填入。示例结构：

```json
{
  "where": "S1.p4.s6",
  "quote": "当前卡住的句子或片段",
  "gaps": ["本轮识别出的缺口"],
  "explained": ["本轮实际讲解的概念"],
  "unexpanded_terms": [],
  "next": "S1.p5",
  "feedback": null
}
```

反馈另追加一行，`where` 保留其对应位置，`feedback` 保存读者原话；未新增讲解时 `explained` 留空。读者档案使用 `known` / `unsure` / `explained` 状态，细则见 SKILL.md。

日志、档案和缓存保留在本机私有数据目录。需要分享到仓库的例子只写论文标识、位置与自己的讲解；论文原文摘录须另核对许可与分享范围，不把私有日志整份复制进去。
