# 每轮输出与记录

按当前阅读阶段使用下面的导读、逐点讲解、完整讲解或走进领域模板；内容跟随读者使用的语言。明确问论文位置或下一篇时直接使用对应模板，不要求先完成导读、卡点或完整讲解。无需为背景登记、错误说明或位置确认硬凑讲解。原句很长时只展示足以定位的片段，并标明省略。来源放在相关解释旁，不另堆一份无法对应主张的书单。

## 全文导读

首次阅读当前论文版本、日志尚无 `type: "overview"` 时输出；用 `log show <paper> --type overview --last 1` 检查，先筛选类型再取最后一条，不能凭未筛选的近期记录判断。读者之后明确要求时可以再给一次。基于已通读的正文和 `outline.md`，对照读者背景，控制在一屏以内：

```text
【全文导读】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
1. 这篇论文在问什么：<一两句，用读者能懂的话>（<位置>）
2. 核心模型 / 实验：
   - 研究对象：……（<式或节>）
   - 调节的参数：……（<位置>）
   - 测量或计算的量：……（<式或图>）
3. 主要结论（作者报告，注明适用范围）：……（<节或图>）
4. 整篇依赖的基础（对照你的背景，可能需要补的）：
   - <基础>：一两句最基础的认识（<论文用到它的位置；背景来源>）
   - ……（2 到 4 项，每项都可以单独展开）
   已在前几篇补过的：<基础>（《<论文>》，你确认懂了／讲过）；……
5. 阅读路线：主线分 N 步：1. <步骤名>（<原文范围>）；2. ……；第一遍可以略读 <节>。
6. 接下来：建议从 <位置> 开始读；贴一句话、说一个词或一幅图都可以；
   也可以说“继续”，我从主线第 1 步讲起。
```

阅读路线使用 `outline.md` 中 3 到 7 个“主线步骤”的名称、编号和原文范围，后续进度沿用它们；旧文件缺此节时由宿主核对全文后只补这一节，其余内容不动。

第 2 项按论文类型取舍：理论论文讲对象、哈密顿量或方程、参数；实验论文讲样品、装置、调节的量和测量的量；数值论文讲模型、数值方法和计算的量。各项都给原文定位，作者主张与背景知识分开，保留结论适用范围；导读是阅读地图，不替代全文，也不把不明确的背景缺口写成事实。

导读前用 `profile concepts --exclude-paper <当前论文>` 对照已有基础；同一 arXiv 编号的其他版本也属于当前论文，不充作跨篇来源。`known` 写“你确认懂了”，`explained` 仅写“讲过”，`unsure` 仍列入需要补的。只引用实际记录的论文和位置；没有其他论文来源时省略“已在前几篇补过的”一行，无 `paper` 来源的概念只能用于判断背景。核对概念的含义、定义和条件后才沿用，不能把相似名称当成同一知识；尤其非厄米 chiral symmetry 与 sublattice symmetry 须逐一核对定义，拿不准就标为待补或待核实。

读者一开始就带着具体句子或疑问时，只把第 1 到 3 项压缩为三到五行简版导读，随后进入下面的逐点讲解。完整和简版导读都在实际输出后单独记录为 `overview`。后续【读到哪了】用一句话带回导读的核心问题。全文尚未读到时，说明限制，不编造导读或提前记录已完成。

## 逐点讲解

一轮只讲一个模型、概念、公式、图，或论证中的一步，通常对应几句话、一个公式或一幅图。读者带来的句子、词、图或一节疑问先定位到原文，再归到所属的点；一句包含两点就分两轮讲。有原句片段才用 `locate`，对核实的段落用 `context`；独立图式从 `paper.json` 按 ID 核对，查看原图／公式并按节读取周边，不补造句子或段落锚点。只有词或节时可用 `find` 或 `text --section`；PDF 直接核实页面，不运行这些结构命令。第一部分只说“继续”时，沿主线选下一个按档案判断需要补基础的点，不要求读者先找一句话。回顾和第二部分的“继续”仍走各自的阶段，不转成第一部分选点。按以下顺序组织：

```text
【这一点】<点的名称>（§<节标题>，<段落／公式／图的编号或范围>）
<用一段或几小段展开原文。交代讨论的对象和必要条件，说明作者在这里具体做了什么、怎样推到这一步或比较了哪些结果，并写出这一步得到的直接结论。>
【这里默认你知道】<必要的知识缺口>（<依据；不确定时标为暂定判断>）
【基础讲解】
<从读者已经会的东西出发，摆出能想象的小场景或能跟着算的小例子。>
<用平实的话写清做了什么或改了什么，以及可以看到、数出或算出什么。>
<给刚才看到的关系命名，写出必要符号、适用条件及可核对的来源。>
合起来：<把例子里的对象和结果对应回这一点，说明为什么这里用得上。>
【回到原文】“<原词>”在这里指……；<符号或公式>表达……；<图>显示……。
（讲解中用到但没展开的词：<列表；没有则写“无”>。不熟就说一声。）
【读到哪了】全文在研究 <核心问题>。前面我们讲过 <与当前点有关的内容>。
这里 <接上前文并说明当前点为后文解决了什么>（<原文位置>）。
接下来 <下一段要讲什么>（<位置>），后面 <用这个结果做什么>。
```

【这一点】写成读者可以独立读懂的一段原文导读，细节随本点展开。讲模型时说清对象、相互作用或关键设定。讲公式时交代关键符号、式子在算什么和成立条件。讲图表时根据已核实的图表内容说明比较对象、对照条件与结果。讲推理时写出从前提到结论的关键一步。先用平实的话说清本点，术语和推导需要的基础在【基础讲解】里展开。

【基础讲解】按这个顺序讲每个实际补上的核心基础。已有合适的小例子时，可以用它串起两个相关基础。用具体数字、两种情况的对照、简单示意或一两步计算，让关键变化真的发生在例子里。类比只保留对得上的关系，并交代它在哪里停止适用。只使用实际需要的概念项，一轮最多 3 个基础概念、向前追 2 层。

读者带来的原句放在【回到原文】中对应，不作标题。只在这种情况下填写记录的 `quote`。用概念名及其 LaTeX 符号查找后文。有核实段落锚点才用 `find --after`，否则省略 `--after`，按原文顺序核实后文命中，再核对上下文与定义。PDF 直接核实后续页码。后文未核实时说明读到的范围，已到正文末尾时说明这一点如何收束主线。

【读到哪了】是每轮最后的一小段，用三四句串起全文问题、此前讲解、当前点在论证中的具体作用和后续内容。依据对话或实际讲解记录写“我们讲过”。第一次从中间切入时，交代“我们从这里切入”，用“原文先……”交代论文已铺垫的内容。优先解释相邻步骤如何相接，例如本段定义的量会怎样用于后面的比较。步骤号可在帮助定位时顺带提及。回看前文时交代这次补回了什么，读到附录时说明它支持或限制哪项正文结论，并给出接回主线的位置。

读者说“这个我会”可跳过，按原有规则只将明确确认范围记为 `known`，不把跳过当成已讲解；单说“继续”不改状态。对于 `pdf_only` / `local_pdf`，所有编号和主线范围都换为核实过的定位，例如“PDF 第 3 页，第 2 段”；区分 PDF 页序与页面印刷页码。不得伪造 HTML 段落编号。全文或某页尚未读取时明确注明相应限制。

## 第一部分回顾与术语表

进入第二部分时，先输出回顾与术语表，等读者回应再给目录；“直接讲／跳过回顾”直接进入目录。读者独立要求回顾或术语表时只给所请求的内容，完成后等待，不用下面的“进入第二部分”结尾催促继续。

读取 `log show <paper> --type overview --last 1`、`log show <paper> --type sentence --last 0` 和 `profile concepts --paper <paper>`，以导读及 `outline.md` 的主线组织真实讲解历史。优先用实际讲解记录的 `step` 归入主线；缺少字段的旧记录核对 `where` 后临时映射，不回写。显式 `step: null` 的主线外讲解单列，不当成缺字段补入主线；无法映射的位置注明未知。长日志先在本地筛出 `point`、`step`、位置、实际 `explained`、缺口及反馈等必要信息。档案中的论文出处可能已被后续阅读更新：本篇讲解历史仍以本篇 `sentence` 日志为准，再定向查这些概念的当前状态，核对含义后使用。不能把导读里略提的词算作补讲，也不能把只有反馈、没有新 `explained` 的行当成新讲解。

回顾一屏以内，每条一到两行；同一基础合并一次并标出各处位置，按主线而非提问时间排列。没有逐点讲解时写“第一部分没有逐点讲解”，只整理已核实的主线和术语表，不虚构卡点或已补的基础。没有可用导读或全文脉络时说明缺口，只使用已核实材料。

```text
【第一部分回顾】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
沿着导读的主线：
  1. <主线的一步>：在 <原文位置> 讲过 <点>，补了 <基础>（一句话）；
     接回原文：<这一步在论证中的作用>
  2. ……
  主线上还没讲到的：<部分及核实过的原文范围>（第二部分会补）
你确认懂了：<概念>（<讲过的位置>）；……／暂无
讲过：<概念>（<讲过的位置>）；……／暂无
仍不确定：<概念>（<有关位置>）；……／暂无
```

只请求独立回顾时，“主线上还没讲到的”只说明缺口，不承诺将进入第二部分。分组依据当前档案；没有状态记录就注明未记录，不凭讲解历史制造确认。`covered` 只列本次回顾中实际涉及的第一部分补讲概念，没有逐点讲解时为空。

用 `glossary-path <paper>` 取得私有 `glossary.md` 的路径与存在状态；该命令不生成内容。术语表覆盖第一部分讲过的概念及所规划第二部分各段会用到的术语和符号，一般 10 到 20 条，不为凑数添加条目；已是 `known` 且本文用法无特别之处的常用词可省略。独立请求时按所需范围整理，不因此启动完整讲解。

整份写入以下固定五列表格，重新生成时整份更新，成功后重新读取核对条目及列结构。只有写入成功才能显示“已保存”；失败时给出可读内容并说明未保存，不伪造保存成功的 `recap`。再次请求时可重生成；已有实际生成的回顾且之后无新 `sentence` 时不主动重复，有新逐点讲解则下次进入第二部分时重新生成。以最近实际生成的回顾为检查点，后续 `recap` 反馈不算新的生成。

只复用实际已输出的部分。结合 `covered`、`terms`、术语表文件存在与实际输出判断，不能把任何一条 `recap` 当作回顾和术语表都已完成；独立请求后进入完整讲解时补齐缺少的部分，再等待回应。没有逐点讲解的回顾本来也可能 `covered: []`，数组为空不单独证明未输出回顾。跨会话缺少实际输出证据、无法确认回顾是否完成时，说明记录不足并补简短回顾，不从空数组推断已完成。

```markdown
# 术语表：<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）

生成于 <实际日期>。状态是生成时的快照，以读者档案为准。

| 术语或符号 | 本文中的意思 | 首次出现 | 讲过的位置 | 状态 |
| --- | --- | --- | --- | --- |
| <术语；符号写成 $...$> | <一句话简化说法；符号注明约定> | <核实的段落或公式编号> | <实际讲解所对应的原文位置；未讲写“—”> | <确认懂了／讲过／仍不确定／未讲> |
```

- 状态按当前档案映射：`known` → 确认懂了，`explained` → 讲过，`unsure` → 仍不确定，无记录 → 未讲。状态和“讲过的位置”分别反映档案与本篇讲解历史；若档案缺失但日志确有讲解，保留真实位置并在表外说明状态未记录，不能据状态推翻日志。
- “本文中的意思”写本文语境下的简化解释；符号保留 LaTeX 写法并注明单位、符号约定或归一化。首次出现要核对原文，不能把第一次补讲的位置当作首次出现；未核实时明确注明。PDF 只用核实过的页码，不补造 HTML 编号。
- 同词异义或同一符号多义分行，并标明语境。分别核对非厄米子晶格对称性与手征对称性的算符定义，不按名称合并；“手征边缘态”也不等同于“手征对称性”。
- 第二部分可指向术语表及讲解位置；严格定义与表中简化说法不同时在该段指出。术语表是状态快照，后续反馈以档案为准，不把保存或展示术语表当作读者确认。

保存成功后展示表格，并按入口选择结尾：

```text
【术语表】共 N 条，已保存到 <glossary.md 的实际路径>
<上面的五列表格>
【接下来】回顾里哪条还不清楚，直接说，我先补上；没有的话说“继续”，
我给出第二部分的目录。
```

独立请求的结尾可用“哪条需要补充或修正，直接告诉我。”不出题，不问“还记得吗”。“继续”只推进已获同意的流程；指出卡点只将相关概念标 `unsure`，用逐点模板补讲并记 `sentence`，再回到回顾，不自动清除 `unsure`。明确确认才按原话覆盖的概念更新 `known` 并保留依据。

同一次回顾中补讲后说“继续”，直接进入目录，不因这次新 `sentence` 重新输出整份回顾并再等待一轮。重新生成规则适用于之后另行进入第二部分，或明确要求重新整理。

## 完整讲解（第二部分）

读者仅表示读完全文时，最多提议一次“先回顾和整理术语表，再完整讲解”，等待同意；已经同意或明确要求时按上节先回顾，等回应后给目录，不再次征求同一授权。读者跳过回顾，或已有可复用回顾且无需重复时，直接给目录。目录按本文核心内容分 3 到 8 段，可与第一段同轮给出；之后每次最多讲一段并等待回应，不能把目录或邀请记作已完成一段讲解。

```text
【完整讲解·目录】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
范围：<本文核心：理论模型 / 实验 / 数值方法；不展开的部分及原因>
第一部分回顾：见上一轮【第一部分回顾】与 glossary.md（跳过时简列真实已讲基础及位置）
分段：
  1. 设定与假设（<原文范围>）
  2. <核心推导或测量流程的一步>（<原文范围>）
  ……
  N. 结论、证据与边界（<原文范围>）
```

每段约一屏，以接近原文的严谨程度解释。理论论文侧重模型、推导和条件；实验论文侧重样品与装置、测量原理、数据处理、误差与对照；数值论文侧重模型、算法、收敛性、有限尺寸效应和统计处理。

```text
【完整讲解·第 k 段】<段标题>（<原文范围>）
<按逻辑顺序讲清本段的设定、推导或测量步骤；定义全部符号、单位及约定，
注明近似和适用条件。省略代数时写明“此处省略……，见式……／附录……”。
区分作者主张、证据支持程度与背景知识，引用对应原文；说明第一部分哪些说法
是简化版本，这里补全了什么。最后一段交代各主要结论的计算、测量或图证据，
作者承认的局限和尚未验证之处。>
【这段用到的基础】<概念>（第一部分在 <位置> 讲过）；……
【读到这里】第 k 段，共 N 段，讲到 <原文范围>。想接着读就说“继续”；
卡在哪里直接说，我会按逐点讲解的方式补上，再回到这一段。
如果这段看懂了或读顺了，也可以直接告诉我。
```

第一部分已讲且档案为 `explained` 或 `known` 的基础可直接使用并标出处（可指向术语表），列入本段 `uses`；`explained` 不代表读者已懂，`unsure` 仍需针对卡点补讲。严格定义与术语表的简化说法不同时明确指出。未讲过且不熟的词当场解释；这类词较多时把漏掉的基础记入 `gaps`。PDF 使用已核实的页码范围，不补造 HTML 编号。

段间等待回应；最后一段按下一段说明补充本篇位置后再等待。单说“继续”只推进，不更新 `known`。读者明确说本段看懂或读顺时，才可按确认范围把该段 `uses` 中的概念记为 `known`，`--source` 保存原话；只确认某个概念就只更新那个。卡住时只把明确涉及的概念记为 `unsure`，用逐点模板补讲、记录为 `sentence`，再回到当前段。补讲不自动清除 `unsure`，不自动推进，不宣称读者已掌握。

最后一段实际讲完后，默认接着给下面的“本篇在领域中的位置”，不再用“继续”暗示还有未讲的段落。之后最多提议一次“下一篇读什么”，等读者同意；邀请不算已经给出推荐，也不更新理解状态。

## 本篇在领域中的位置与下一篇读什么

本篇位置默认在第二部分最后一段之后给出，首次导读不展开；读者随时明确问位置时可直接给。用本篇引言、正文中的依赖或对照关系选文献，再用 `ref` 取对应条目与 `doi` / `arxiv_id`，用 `lookup <DOI|arXiv 编号>` 查来源并实际阅读。

```text
【本篇在领域中的位置】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
- 奠基工作：<参考文献编号与简称>——来源大致研究了……；
  本文作者在 <位置> 将它用于／描述为……（核对：摘要／全文，<链接>）
- 直接前作：……
- 对照工作：……
```

通常列本篇直接依赖或对照的 3 到 5 项，按实际角色取舍，不必凑齐所有类别。核实不足时只列已核实项并说明缺口；一项都未核实时只说明限制，不写空的完成记录。作者对前作的描述与来源核对后的事实分开写，例如“本文作者称不同于 [41]”不等于已独立确认该差异。仅核对摘要时只说明工作大致做了什么；具体结论、差异或优先权须核对原文相关部分并给出位置。

第二部分和本篇位置都结束后，结合当前对话和 `log show <paper> --type field --last 5`，最多邀请一次推荐后续阅读，等读者同意。拒绝、沉默和到达末段都不算同意。读者主动问下一篇时直接推荐，不再次征求确认，也不要求先完成本篇位置或第二部分。

```text
【下一篇读什么】
1. <文献>（补基础的讲义或综述）：为什么读……；
   按你的档案还缺：……（暂定；讲过但未确认的……／仍不确定的……）
   （核对：摘要／全文，<链接>）
2. <文献>（奠基论文）：为什么读……；按你的档案还缺：……（暂定）
   （核对：摘要／全文，<链接>）
3. <文献>（相关的新工作）：为什么读……；按你的档案还缺：……（暂定）
   （核对：摘要／全文，<链接>）
```

最多 3 篇，按需要取舍类别和数量；缺少可核实来源时少列，不为凑书单添条目。优先从本篇参考文献中选，使用宿主检索得到的外部候选同样须经 `lookup` 查来源并实际核对。理由限定在读过的内容能支持的范围；缺少的基础是按档案的暂定判断，不把 `explained` 当作 `known`，也不把未知背景当成确定缺口。未发现缺口时可写“档案中暂未发现明确缺口”，记录的 `missing` 可为空数组。

`lookup` 返回标题、作者、年份、摘要、来源服务及链接，缓存命中时可离线复用，用 `--refresh` 才重新请求。查到标题或条目不等于核实科学内容；`abstract: null` 不能标“核对：摘要”，应另行打开来源。服务不可用且无可用缓存、或来源不可读时说明限制，未核实条目不纳入输出或 `field`。`checked` 按实际读过的层次填写，不能因工具成功就自动标为 `abstract` 或 `fulltext`。不扩展为长篇领域综述、文献史或自动引用网络。

## 全文脉络 outline.md

用 `outline-path` 返回的路径保存。用 `text <paper>` 通读，或以 `text <paper> --section <节编号>` 分节读完全文；需要完整结构时仍可读 `paper.json`，PDF 使用宿主阅读能力。通读后写入并按版本复用；它是宿主使用的脉络材料，面向读者的导读还需按背景调整：

```markdown
# <标题>（<arXiv 编号与版本；本地 PDF 则用缓存标识>）

## 论文主线
三到五句：研究问题、方法、主要结论及必要的范围限定。

## 主线步骤
1. <步骤名>（<原文范围，如 S1–S2.SS1>）：一句话说明这一步做什么。
2. ……（共 3 到 7 步，覆盖正文主线；附录和可以略读的节不编号）

## 各节作用
- <节编号与标题>：这一节怎样推进论证；引入了哪些当前阅读需要的概念。
```

旧 `outline.md` 缺少“主线步骤”时，宿主核对原文后只补这一节，保留其他内容；PDF 的范围用页码。已有步骤的编号与含义保持稳定，不能因补节而改释历史 `step`；不一致时先核对。步骤映射由宿主完成，工具不解析 `outline.md`。

## 私有讲解记录

每次导读、逐点讲解、回顾与术语表、完整讲解的一段或走进领域的一个分支各以一个 JSON 对象传给 `log add <paper> --json -` 的标准输入。记录真实内容，不原样运行示例，不把占位文本写进档案。`time` 使用真实时间；若省略，由工具填入。`type` 默认为 `sentence`；旧记录缺少 `type` 时也按逐点记录理解，读取和筛选时不改写旧文件。

`deep` 必须有从 1 开始的正整数 `segment`，不能用布尔值、零、小数或字符串代替。`uses` 为字符串数组，可为空；省略时默认为 `[]`。`sentence`、`overview`、`recap` 和 `field` 不得带 `segment`，即使值为 `null` 也不允许。`uses` 记录本段直接使用的、第一部分已讲基础；`explained` 只记本次实际补充解释的内容，不能把全部 `uses` 误写成新讲过的基础。

`sentence` 可带 `point`（字符串）和 `step`（JSON 正整数或 `null`）；两者都可省略，旧记录照常读取，不补写缺字段。`step` 不接受布尔值、零、负数、浮点数或数字字符串；其他类型不得带 `step`，即使是 `null` 也不允许。`where` 可为句子、段落、公式、图的编号或范围，`step` 由宿主按原文位置映射到主线，已核实在主线之外才用 `null`；尚无法映射时省略 `step` 并说明未知，不能用 `null` 代替未知。

逐点讲解示例（名称、步骤和范围须替换成当前论文的实际映射）：

```json
{
  "type": "sentence",
  "point": "本轮讲解的点",
  "step": 1,
  "where": "S1.p4.s6",
  "quote": "读者确实带来的原句或片段；未带原句时用空字符串",
  "gaps": ["本轮识别出的缺口"],
  "explained": ["本轮实际讲解的概念"],
  "unexpanded_terms": [],
  "next": "S1.p5",
  "feedback": null
}
```

由“继续”选点、没有读者原句时，`quote` 留空；主线之外的格式如下：

```json
{"type": "sentence", "point": "附录中的一个点", "step": null, "where": "A1.p2", "quote": "", "explained": ["本次实际补讲的基础"], "feedback": null}
```

纯反馈另记一行，保留正在回应的点与步骤，不把未讲的下一点算成进度：

```json
{"type": "sentence", "point": "本轮讲解的点", "step": 1, "where": "S1.p4.s6", "quote": "", "explained": [], "next": "S1.p5", "feedback": "继续"}
```

`next` 只表示计划接读位置。没有可核实的当前点／步骤时省略相应字段；不要从反馈推造新进度。

导读单独记录，`where` 为 `null`；简版只记录实际讲过的内容，不把尚未讲的基础加入 `explained`：

```json
{
  "type": "overview",
  "where": null,
  "quote": "",
  "gaps": ["对照读者背景暂定的基础缺口"],
  "explained": ["导读中实际解释过的模型或基础概念"],
  "unexpanded_terms": [],
  "next": "S1.p1",
  "feedback": null
}
```

反馈另追加一行，`where` 保留其对应位置（导读反馈可为 `null`），`feedback` 保存读者原话；未新增讲解时 `explained` 留空，也不把单纯反馈记为一次新的 `overview`。读者档案使用 `known` / `unsure` / `explained` 状态：只有读者明确确认理解才记为 `known` 并保存原话，细则见 SKILL.md。

回顾与术语表实际输出，且本次术语表写入成功后，记录 `recap`；只请求回顾而未生成术语表时 `terms` 留空，只请求术语表时 `covered` 留空。`where` 必须为 `null`，`covered` 与 `terms` 都是字符串数组，可为空，省略时补 `[]`；`terms` 与本次保存的术语表条目一致。回顾只是整理已有解释，不能把全部 `covered` 写成新讲解。

```json
{
  "type": "recap",
  "where": null,
  "covered": ["第一部分实际补讲并在回顾中涉及的概念"],
  "terms": ["本次术语表的条目，与 glossary.md 一致"],
  "explained": [],
  "feedback": null
}
```

读者对回顾的反馈另记一行，保存原话，未重新生成内容时 `covered`、`terms` 留空，不把反馈记成一次新生成：

```json
{"type": "recap", "where": null, "covered": [], "terms": [], "explained": [], "feedback": "继续"}
```

邀请或“跳过”不写 `recap`。用 `log show <paper> --type recap --last 5` 查近期回顾与反馈，必要时扩大范围，在本地按日志顺序比较最近实际生成回顾与后续 `sentence`，不要只比较最新一条反馈。日志追加本身不修改档案；“继续”不更新理解状态，确认或卡点另按档案规则处理。

完整讲解的一段记录示例（`where` 为该段覆盖的原文范围）：

```json
{
  "type": "deep",
  "segment": 1,
  "where": "S2.SS1–S2.SS2",
  "quote": "",
  "uses": ["哈密顿量", "边界条件"],
  "gaps": [],
  "explained": [],
  "unexpanded_terms": [],
  "next": "S2.SS3",
  "feedback": null
}
```

读者回应另写一行，保留本段 `segment`、`where` 和 `uses`。以下示例是不同反馈分支，不代表实际发生的对话，也不能依次照写进私有日志：

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "explained": [], "next": "S2.SS3", "feedback": "继续"}
```

这条仅请求下一段，不执行 `profile mark ... known`。

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "explained": [], "next": "S2.SS3", "feedback": "这一段读顺了，哈密顿量和边界条件都看懂了"}
```

这条明确覆盖两个 `uses` 概念，可分别 `profile mark` 为 `known`，`--source` 使用该条原话，`--where` 保留当前范围。若原话只确认哈密顿量，就只更新哈密顿量。

```json
{"type": "deep", "segment": 1, "where": "S2.SS1–S2.SS2", "uses": ["哈密顿量", "边界条件"], "gaps": ["边界条件"], "explained": [], "next": "S2.SS1–S2.SS2", "feedback": "我还是卡在边界条件这里"}
```

这条只把边界条件记为 `unsure` 并保存原话；定位到实际疑问所属的点，按逐点模板补讲后回到第 1 段。反馈行不是新讲解段，不能增加段号；补讲记录也不能代替读者确认。

用 `log show <paper> --type deep --last 5` 查看近期完整讲解及反馈，必要时增加数量。类型筛选在 `--last` 截取前进行；`--last 0` 返回该类型的全部记录。恢复进度时结合实际讲解条目（通常 `feedback: null`）、对应反馈和 `segment` 判断；不要按行数计段，也不要将 `next` 所指的位置当成已讲完的位置。

本篇位置与后续推荐各在实际输出后写一条 `field`，`where` 必须为 `null`，`kind` 为 `position` 或 `next`。`items` 为对象数组，每项包含 `label`、非空的 `title`、`role`、`checked` 和可访问来源的 HTTP(S) `link`；`position` 的 `label` 是非空的本篇参考文献标识，`next` 的 `label` 无本篇编号时可用空字符串或 `null`。角色按分支取值：`position` 为 `foundational` / `predecessor` / `contrast`，`next` 为 `notes` / `foundational` / `recent`。`checked` 仅为 `abstract` / `fulltext`；`next` 每项还须有字符串数组 `missing`，允许为空。记录不包含未核实候选，不使用 `segment`，邀请和服务失败均不记成已完成。

以下只展示格式，标题、编号、链接及缺口须替换为实际核实的内容；一项示例不代表已完成足量核实：

```json
{
  "type": "field",
  "where": null,
  "kind": "position",
  "items": [
    {
      "label": "[26]",
      "title": "<已核实的前作标题>",
      "role": "predecessor",
      "checked": "abstract",
      "link": "https://example.org/verified-source"
    }
  ]
}
```

```json
{
  "type": "field",
  "where": null,
  "kind": "next",
  "items": [
    {
      "label": "",
      "title": "<已核实的讲义或综述标题>",
      "role": "notes",
      "checked": "fulltext",
      "link": "https://example.org/verified-reading",
      "missing": ["<按档案暂定需要补的基础>"]
    }
  ]
}
```

用 `log show <paper> --type field --last 5` 恢复已给出的论文位置和推荐，`--last 0` 仅在需要全部该类型记录时使用。字段记录本身不更新 `known` / `explained` / `unsure`；已给出书单也不意味着读者读过或学会了其中内容。

日志、档案和缓存保留在本机私有数据目录。需要分享到仓库的例子只写论文标识、位置与自己的讲解；论文原文摘录须另核对许可与分享范围，不把私有日志整份复制进去。
