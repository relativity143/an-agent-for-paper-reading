# 每轮输出与记录

按当前阅读阶段使用下面的导读或逐句讲解模板；内容跟随读者使用的语言。无需为背景登记、错误说明或位置确认硬凑讲解。原句很长时只展示足以定位的片段，并标明省略。来源放在相关解释旁，不另堆一份无法对应主张的书单。

## 全文导读

首次阅读当前论文版本、完整日志尚无 `type: "overview"` 时输出；用 `log show <paper> --last 0` 检查，不能凭近期记录判断。读者之后明确要求时可以再给一次。基于已通读的正文和 `outline.md`，对照读者背景，控制在一屏以内：

```text
【全文导读】<标题>（<arXiv 编号与版本；本地 PDF 用缓存标识>）
1. 这篇论文在问什么：<一两句，用读者能懂的话>（<位置>）
2. 核心模型 / 实验：
   - 研究对象：……（<式或节>）
   - 调节的参数：……（<位置>）
   - 测量或计算的量：……（<式或图>）
3. 主要结论（作者报告，注明适用范围）：……（<节或图>）
4. 整篇依赖的基础（对照你的背景，可能需要补的）：
   - <基础>：一两句最基础的认识（<论文用到它的位置；背景来源>）
   - ……（2 到 4 项，每项都可以单独展开）
5. 阅读路线：主线是 <节和图的顺序>；第一遍可以略读 <节>。
6. 接下来：建议从 <位置> 开始读；哪句卡住就贴给我。
```

第 2 项按论文类型取舍：理论论文讲对象、哈密顿量或方程、参数；实验论文讲样品、装置、调节的量和测量的量；数值论文讲模型、数值方法和计算的量。各项都给原文定位，作者主张与背景知识分开，保留结论适用范围；导读是阅读地图，不替代全文，也不把不明确的背景缺口写成事实。

读者一开始就带着具体卡住的句子时，只把第 1 到 3 项压缩为三到五行简版导读，随后进入下面的逐句讲解。完整和简版导读都在实际输出后单独记录为 `overview`。之后的逐句讲解沿用这里建立的图景，不重复导读；“放回全文”以这条主线为参照。全文尚未读到时，说明限制，不编造导读或提前记录已完成。

## 逐句讲解

按以下顺序组织，保留各项：

```text
【卡住的位置】§<节标题>（<句子编号>）：“<原句或明确省略的片段>”
【这句默认你知道】<必要的知识缺口>（<依据；不确定时标为暂定判断>）
【基础讲解】
1. <基础概念>：只讲这里用到的一面，给必要条件及背景来源。
2. <需要时的第二个概念>：……
3. <需要时的第三个概念>：……
合起来：<这些基础怎样组成原句的含义>。
【回到这句话】“<原词>”在这里指……；“<符号/公式/图>”在这里表达……。
【放回全文】这一段在 <节> 中负责……；前文 <位置> 已经……；
后文 <核实的位置> 还会用到“<概念>”，用于……。
【接着读】从 <下一段编号> 开始，留意 <与当前卡点直接相关的一点>。
（讲解中用到但没展开的词：<列表；没有则写“无”>。不熟就说一声。）
```

只使用实际需要的概念项。若尚未找到后文出现的位置，在“放回全文”中写明未查到；没有下一段时说明已到正文末尾。概念名及其 LaTeX 符号都要搜，并核对上下文与定义；不要补造编号或把单纯的词或符号命中写成已验证的论证关系。

对于 `pdf_only` / `local_pdf`，把所有编号换为核实过的定位，例如“PDF 第 3 页，第 2 段”；区分 PDF 页序与页面印刷页码。不得伪造 HTML 段落编号。全文或某页尚未读取时明确注明相应限制。

## 全文脉络 outline.md

用 `outline-path` 返回的路径保存。用 `text <paper>` 通读，或以 `text <paper> --section <节编号>` 分节读完全文；需要完整结构时仍可读 `paper.json`，PDF 使用宿主阅读能力。通读后写入并按版本复用；它是宿主使用的脉络材料，面向读者的导读还需按背景调整：

```markdown
# <标题>（<arXiv 编号与版本；本地 PDF 则用缓存标识>）

## 论文主线
三到五句：研究问题、方法、主要结论及必要的范围限定。

## 各节作用
- <节编号与标题>：这一节怎样推进论证；引入了哪些当前阅读需要的概念。
```

## 私有讲解记录

每次导读或逐句讲解各以一个 JSON 对象传给 `log add <paper> --json -` 的标准输入。记录真实内容，不原样运行示例，不把占位文本写进档案。`time` 使用真实时间；若省略，由工具填入。`type` 默认为 `sentence`；旧记录缺少 `type` 时也按逐句记录理解，不能当作导读。

逐句讲解示例：

```json
{
  "type": "sentence",
  "where": "S1.p4.s6",
  "quote": "当前卡住的句子或片段",
  "gaps": ["本轮识别出的缺口"],
  "explained": ["本轮实际讲解的概念"],
  "unexpanded_terms": [],
  "next": "S1.p5",
  "feedback": null
}
```

导读单独记录，`where` 为 `null`；简版只记录实际讲过的内容，不把尚未讲的基础加入 `explained`：

```json
{
  "type": "overview",
  "where": null,
  "quote": "",
  "gaps": ["对照读者背景暂定的基础缺口"],
  "explained": ["导读中实际解释过的模型或基础概念"],
  "unexpanded_terms": [],
  "next": "S1.p1",
  "feedback": null
}
```

反馈另追加一行，`where` 保留其对应位置（导读反馈可为 `null`），`feedback` 保存读者原话；未新增讲解时 `explained` 留空，也不把单纯反馈记为一次新的 `overview`。读者档案使用 `known` / `unsure` / `explained` 状态：只有读者明确确认理解才记为 `known` 并保存原话，细则见 SKILL.md。

日志、档案和缓存保留在本机私有数据目录。需要分享到仓库的例子只写论文标识、位置与自己的讲解；论文原文摘录须另核对许可与分享范围，不把私有日志整份复制进去。
