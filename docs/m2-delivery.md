# M2 后端交付：本篇概念记录与反馈

2026-11-15。实现依据为 `gpt-m2-handoff.md` 与 `agent-architecture.md` 4.7 节。本轮完成后端与离线验收，未修改 `web/` 或架构文档，也未调用真实模型。

## 已完成

每篇论文拥有独立、可编辑、带版本的概念记录。显示回执更新实际展开的概念；读者反馈更新理解状态；下一轮提示使用读者确认的最新版本。旧 `profile.json` 与旧日志既不初始化记录，也不作为模型的基础判断来源。M2 的显示回执不再写旧 `profile.json`。

记录作为 `agent-state.json` 的 `concept_record` 保存，与讲解、显示回执共用 `.agent.lock` 和原子文件替换。无记录时 GET 返回 `{"version":0,"concepts":[]}`，不为读取而写入或迁移文件。存量记录损坏时保留原文件并报错，不重置为空。

| 接口 | 请求与成功响应 | 主要错误 |
| --- | --- | --- |
| `GET /api/papers/<paper>/record` | 完整 `{version, concepts}`；每条含 `name/status/explained_in/where/note/updated` | 损坏记录 400，保留原文件 |
| `PUT /api/papers/<paper>/record` | `{version, concepts:[{name,status,note?}]}`；返回替换后的完整记录 | 非法字段、名字、状态、条数 400；版本过期或本篇生成中 409 |
| `POST /api/papers/<paper>/feedback` | `{explanation,kind,concept?,note?}`；返回最新完整记录 | 非法字段 400；讲解不存在 404；本篇生成中 409 |
| `POST /api/papers/<paper>/explain` | 原请求增加必填 `record_version`；`reading_context` 仍必填，`reading_session` 仍可选；成功仍为 202 和任务编号 | 缺版本、布尔/浮点/负数版本 400；版本不符 409；拒绝时不创建任务、不调用模型 |

`known`、`explained`、`unsure` 的转换、大小写不敏感的名字去重、80 字名字/200 字备注/300 条上限均按 4.7 实现。`PUT` 保留同名条目的讲解来源，新手动条目的来源为 null。记录只在实际内容改变时增加一次版本；原样 PUT 不变，清空已有记录仍递增版本，不回到 0。清空概念记录不删除讲解历史，也不重置主线位置。时间按 `updated` 从新到旧排列，同时间并列。

导读、`assumes`、`unexpanded` 不因显示而登记为已讲。逐点讲解只登记 `concepts`；已有 `known/unsure` 不被自动改为 `explained`，但更新最近讲解来源。重复显示回执不会再次添加或增加版本。超过记录容量或概念名字不合法的模型输出会进入现有的一次修正流程，不让不可登记的新卡片通过生成校验。

## 下一轮怎样使用记录

生成前同步检查 `record_version`，在工作线程和保存结果前再次核对。生成期间禁止修改或反馈本篇记录；另一篇论文的记录互不影响。未首次确认显示的卡片也不会在本篇生成中修改记录，返回 409 可重试；已确认过的重复回执不重复改记录。

模型材料包含完整 `concept_record`，与开头背景冲突时以记录为准：`known` 直接用，`explained` 首次带一句提醒，`unsure` 实际用到时换讲法重讲。`unsure_previous_explanations` 只提取 `explained_in` 指向的本篇讲解中同名概念的旧讲法，不夹带那份讲解的旧背景假设。没有有效来源时不编造旧讲法。

`assumes.status` 与本次记录按去空白、大小写不敏感的名字匹配；`explained_at` 必须等于记录的 `where`。未记录概念使用 `new/null`。HTML 来源取讲解位置的第一个真实 ID，PDF 使用 `PDF 第 N 页`，不把多个 ID 拼成校验器不接受的来源。跨篇 `previously` 仍为空，不修改讲解对象的公开字段或放宽原定位校验。

最新逐点讲解收到 `unclear` 后，只要还没有生成新讲解，下一次正常 `continue` 就在原位置换讲法，HTML 位置须相交、PDF 页码须相同，`progress.step` 不变。即使原来 `next=null`，也允许重讲；生成失败或取消不消耗这次重讲意图。成功生成新讲解后，之后的继续按新的 `next` 走。明确的 `ask`（包括等待回答的排队问题）优先回答所选位置，不被重讲规则覆盖。

## 恢复与边界情况

- **反馈去重。** 契约没有单独的客户端操作 ID，因此以同一讲解上规范化后的 `kind/concept/note` 内容识别重复反馈，概念名不分大小写。同一动作重试只返回当前记录，不重新应用状态或重复写日志；即使中间又编辑过记录，也不会让旧重试覆盖新状态。需要主动改变状态时，使用不同反馈或 PUT。省略 note 保留旧备注，显式 null 清除备注。
- **反馈与显示回执互不冒充。** 反馈日志带独立 `feedback_id`，`explained` 为空；显示回执去重排除反馈日志，反馈先到也不会漏记实际阅读日志。
- **日志写入失败。** 记录、反馈去重标识和待写日志先在同一次原子替换中落盘，再追加现有 `log.jsonl`。若追加失败，或追加成功后清空待写项失败，再次提交反馈会补齐，版本和日志不重复。不是启动即自动重放，也不声称跨两个文件同时提交。
- **未显示卡片遇到记录修改。** 内部保存每份讲解生成时的记录版本；未显示卡片使用旧版本时，`explain` 返回 409，不把它当作按新记录生成的结果。页面先从历史恢复并确认显示，再 GET 记录和继续。旧卡片仍保留原样，不擅自删除、跳过或篡改阅读记录。此前没有版本标记的卡片按初始版本 0 处理。
- **对导读反馈。** `unclear` 可以记反馈日志，但导读没有实际展开的 `concepts`，因此不新增状态、不触发逐点重讲。`stuck/known` 可以新增明确指定的词。对较早卡片的反馈会更新概念状态，但只有最新逐点卡片触发下一次原位重讲。
- **反馈中新词的来源。** 若被引用的逐点卡片确实展开过这个词，可关联该卡片；否则新增词的来源为 null。PUT 新增条目始终为 null。

## 给 Claude 的联调说明

公开讲解对象、SSE 事件与 `backend.generate(prompt, schema)` 签名不变；`Application` 构造方式不变。页面应按 4.7 在打开时确认已有记录，每次回执、反馈或编辑后读回/接收最新记录版本。`record_version` 不写进 `asked` 或 `pending`，后台不会替旧版页面猜版本。

当前 `web/dev/fixture_server.py` 的普通 HTML 队列在不插入反馈时，逐轮 `assumes` 与新记录一致，已做无模型调用的静态核对。**反馈分支需要 Claude 调整样例**：固定队列不会根据 `repeat_point` 返回原位置，也不会根据记录里的新 `known/unsure` 改 `assumes`，不能用它直接证明 M2 反馈闭环。让假模型读取本轮材料里的 `concept_record`、`repeat_point`，返回对应位置和状态；不要降低后端校验来配合旧样例。PDF 同理。

记录读取 404 时的旧后端回退仍由页面负责；M2 后端的记录接口已存在，`record_version` 就是必填。遇到上述未显示旧卡片的 409 时，可复用历史恢复和显示回执流程，再重新取得版本；不要直接重试旧版本。
