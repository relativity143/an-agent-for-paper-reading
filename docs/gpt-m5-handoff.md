# 给 GPT：M5 读完之后的四个阶段（后端）

2026-11-16，Claude 写。接口以 [agent-architecture.md 的 4.10 节](agent-architecture.md) 为准；各阶段的内容要求在 [implementation.md](implementation.md) 的 8.3、8.4、8.5 和 6.4 节，那是原 Skill 的定义，这一轮把它搬到网页的后端。页面由 Claude 做，先用样例数据，后端就绪后再联调。

## 背景

用户认为这一部分很重要，要先做掉，方便他试读：读完一篇之后，能回顾讲过什么、拿到一份术语表、听一遍严格的完整讲解、知道这篇在领域里的位置和下一篇读什么。

## 要做的

### 1. `explain` 的四种新 `mode`

`recap`、`deep`、`position`、`next_reading`，返回的对象、字段和规则见 4.10 节。和逐点讲解共用同一套任务、事件流、停止、修正一次、显示回执和历史记录；`reading_context`、`record_version` 的要求不变。

- 没有导读时四种都不启动任务。
- `deep` 自己记进度：没有目录就生成目录，有目录就讲下一段，全部讲完后以中文 `error` 说明已经讲完。目录定下来以后不重新生成。生成失败或被停止不算讲过这一段。
- `continue` 和 `ask` 的行为不变，可以和新模式穿插。`ask` 之后再 `deep`，接着讲原来该讲的那一段。
- 最新一份讲解还没确认显示时，新模式和 `continue` 一样先返回它。

### 2. 提示

每种模式一份提示，内容要求照 implementation.md 的对应小节，并且：

- **回顾**只依据这篇论文实际的讲解历史和概念记录，不依据导读里一笔带过的内容；没有逐点讲解时如实说明。按主线的步骤组织，不按时间。
- **术语表**的 `status` 和 `explained_at` 由后端按概念记录填，不让模型判断。
- **完整讲解**不再为读懂而简化；概念记录里 `unsure` 的基础不能当作已会；最后一段必须有证据链。
- **领域位置和下一篇**不出题、不凑数。`checked` 由后端按实际交给模型的材料填：只给了本文的引用上下文就是 `citation`。要不要在后端取被引文献的摘要来核对（原 Skill 用 `lookup` 做这件事），由你决定；取了才能写 `abstract`，没取就老实写 `citation`，这时 `said_by` 只能是 `authors`。取摘要要联网：失败时退回 `citation`，不要让整轮失败。
- 旧的 `profile.json` 和日志仍然不进提示。

### 3. 校验

4.10 节逐条写了的都要校验，包括：段号连续且和目录一致；`foundations` 里 `taught` 与 `itself`、`explained_at` 的对应；`unsure` 的基础不能 `taught: false`；最后一段有 `evidence`；`ref` 是参考文献里有的编号；链接来自参考文献；条数上限。

### 4. 显示回执之后

- `deep` 的一段：`taught` 为 `true` 的基础按 4.7 记进概念记录。
- `recap`：把术语表存成这篇论文的 `glossary.md`（格式见 implementation.md 6.4 节），整份重写。
- 各种类型按现有规则写日志（`recap`、`deep`、`field`）。

### 5. `GET /api/health` 的 `features`

加一个字符串数组，支持这一轮的功能时包含 `"stages"`。顺手把已有的可选功能也列上（`"record"`、`"map"`、`"prerequisites"`），页面以后可以据此判断，不用靠 404。

## 不要做的

- 不改页面（`web/`）。页面缺什么，在交付说明里提出来。
- 不做跨论文的积累和读者文献库：`previously` 仍然为空。
- 不出题、不打分，不替读者把概念标成“已经会”。
- 不放宽现有的校验，不增加重试次数，不改逐点讲解和导读的对象。

## 验收

每一条要有离线测试，用隔离的数据目录和测试桩。

| 场景 | 要看到的结果 |
| --- | --- |
| 没有导读时请求四种模式 | 400，不调用模型 |
| `recap`，有两轮逐点讲解 | 提示里有讲解历史和概念记录，没有旧档案；输出通过校验后保存 |
| `recap`，没有逐点讲解 | 提示要求如实说明；`steps` 为空、`note` 非空的输出通过 |
| 术语表里的词在概念记录里是 `unsure` | 返回的对象里它的 `status` 是 `unsure`，不管模型写了什么 |
| 术语表里的词不在记录里 | `status` 是 `untaught`，`explained_at` 是 `null` |
| `recap` 确认显示后 | `glossary.md` 写出，内容和对象一致；再生成一次会整份重写 |
| 第一次 `deep` | 返回目录；段数不在 3 到 8 之间的输出不通过 |
| 之后的 `deep` | 依次返回第 1、2、… 段；段号跳号、标题或范围和目录不一致的输出不通过 |
| 最后一段没有 `evidence` | 不通过 |
| 记录里 `unsure` 的基础写成 `taught: false` | 不通过 |
| 一段确认显示后 | `taught: true` 的基础进了概念记录，版本加一 |
| 讲到一半 `ask`，再 `deep` | 回答是逐点讲解；之后的 `deep` 是原来该讲的那一段 |
| 讲到一半 `deep` 失败或被停止 | 下一次 `deep` 还是同一段 |
| 全部讲完后再 `deep` | 中文 `error`，不调用模型 |
| `position` 里 `ref` 不在参考文献里，或链接不是参考文献里的 | 不通过 |
| 只给了引用上下文 | 返回的 `checked` 是 `citation`；`said_by` 是 `source` 的输出不通过 |
| `next_reading` 超过 3 篇，或本篇之外的文献 `checked` 是 `citation` | 不通过 |
| PDF 论文 | 各种对象的位置用页码和原文摘录，校验同逐点讲解 |
| 重启服务 | 目录和讲到第几段都还在 |
| `GET /api/health` | `features` 里有 `stages` |

现有全部离线测试仍然通过。`web/dev/fixture_server.py` 的假模型目前只认导读、逐点讲解和基础清单；新模式的固定输出由 Claude 补，你只需要保证“本轮材料”里能看出这一轮是哪种模式（比如 `type` 字段），并在交付说明里写明。
