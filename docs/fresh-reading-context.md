# 每次阅读重新询问基础

2026-11-15。适用于独立 Agent 的网页和 `server/`，按读者要求停用旧档案对讲解起点的自动判断。

**开场顺序更新：** 现在先说明本文需要哪些基础，再由读者逐项选择“已经会／需要补／不确定”，最后补充目标并开始导读。下文“打开时先填写基础”的界面流程已被取代；每次重新确认、禁止自动沿用旧档案的原则不变。见 [基础清单交付](prerequisites-first-delivery.md) 与架构 4.9。

**M2 更新：** 本文记录此前的初次询问改动。现在新增本篇独立概念记录，读者打开时先确认或修改，之后随讲解和反馈更新；`explain` 必须携带当前 `record_version`。下文“一律 new”“只使用页面内存中的状态”由 [M2 交付](m2-delivery.md) 的规则取代。不读取旧全局 `profile.json`、不迁移旧日志的约束不变。

## 读者看到的变化

每次打开或刷新一篇论文，先询问本次已经学过哪些基础、哪些词不熟悉、希望读到什么程度。输入框不预填旧记录；也可以明确选择“从基础讲起”。确认前不调用模型。确认后由读者点击“继续”或“提问”生成，沿用已有的显示确认、停止和模型选择流程。

输入框的回答只在当前页面内存保留，并随本次生成请求交给模型；不放入浏览器存储，也不自动登记到 `profile.json`。生成的讲解仍按原流程保存，可能用自然语言提及这次的起点，但之后的页面不会据此推断基础。同一页面内连续读下去无需每轮重填，可以修改本次基础；重新确认、刷新、换论文或浏览器返回缓存页面时使用新的阅读会话。

历史讲解仍可查看，原文位置和主线进度可以恢复。旧讲解中写过的“你会什么”、旧 `known/unsure/explained` 状态、跨篇基础与旧背景都不决定新一轮的讲法。历史卡片不会被改写成新卡片。

## 接口与边界

`POST /api/papers/<paper>/explain` 在原请求上增加：

```json
{
  "mode": "continue",
  "reading_context": "学过线性代数，但不了解这篇论文中的专业术语；先解释基本概念。",
  "reading_session": "8a649cbc-0883-456d-b884-6a52670ca830"
}
```

- `reading_context` 必填，去掉首尾空白后为 1–2000 字符；缺失或非法返回 400，任务不启动。
- `reading_session` 是网页每次确认时新建的随机 UUID。服务接受 16–80 个字母、数字、下划线或连字符；省略时仍可生成，但不恢复本页多轮讲解上下文。
- 两个输入字段在生成前从提问请求中取出，不作为字段进入 `pending`、`asked`、历史对象或档案；这不保证生成正文完全不提及读者此次说明。重启后继续回答排队问题也必须提供新的本次基础。
- 后端不再调用 `profile()` 或读取旧日志来构造模型材料。旧历史只保留位置、步骤和下一位置摘要。
- 后端用有限的内存索引记录本页生成的讲解 ID，最多 128 个会话、每会话最近 6 轮；同一页面可续讲未完成的基础。修改背景或重启服务后不再取出前一会话的讲解正文。索引不落盘。
- `previously` 必须为空；本轮 `assumes.status` 为 `new`、`explained_at` 为 `null`，表示没有沿用档案里的确认状态，不代表读者肯定没学过。界面标签为“本轮基础”，具体起点由 `note` 用自然语言说明。
- 模型仍需先补必要基本术语和物理图像，再进入推导；“继续”和展示过一张卡片都不等于掌握。显示回执仍保存实际阅读记录，供历史查看；不会因本次修改删除旧数据。

旧版 API 调用方需要补 `reading_context`。这是明确的行为调整，不为旧客户端默认代填背景。旧 Skill 的手动工作流不在本次修改范围，独立服务的背景规则覆盖共享模板中的旧档案用法。
