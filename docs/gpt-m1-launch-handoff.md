## 任务，按优先顺序

### 1. 双击启动

在仓库根目录加 `start.command`（macOS），带可执行权限提交。

双击后的行为：

- 进入仓库目录，找到可用的 Python（3.10 或以上）。找不到时用一句话说明要装什么，不要直接报一串错误。
- 默认端口上已经有本服务在运行（`/api/health` 能返回本服务的版本）时，只打开页面，不再启动第二个。
- 否则启动服务并打开页面，相当于 `python3 -m server --open`。
- 默认端口被别的程序占用时，换一个空闲端口，并把实际地址打印出来。
- 窗口里用中文写清楚三件事：服务的地址、现在用的模型后端、怎样停止（关掉这个窗口，或按 Ctrl+C）。
- 关掉窗口后服务要停下来，不留后台进程。

它使用读者真实的 `~/.paperread/`，不设置 `PAPERREAD_HOME`。

在 `server/README.md` 里写明用法，并说明一点：从 GitHub 下载压缩包得到的文件，第一次双击可能被系统拦下，需要在访达里右键选“打开”。

### 2. 设置接口

实现 `GET /api/settings` 和 `PUT /api/settings`，结构见 4.5 节。

- `GET` 返回当前选用的后端、三个后端各自的 `available`、`configured`、`authenticated`，以及 `api` 的 `base_url`、`model`、`key_configured`。
- `PUT` 只接受 `{"backend": "<claude|codex|api>"}`。请求体里出现别的字段时返回 400，不要悄悄忽略；尤其不能接受密钥。
- 所选后端的 `available` 为 `false` 时返回 400，并用一句话说明原因（例如没有找到 Codex 的命令行程序，或 API 还没有在配置文件里填好）。
- 有讲解正在生成时返回 409。
- 切换后，下一轮讲解就用新的后端，不需要重启服务。`GET /api/health` 的 `backend` 同步变化。
- 写 `config.json` 时保留文件里的其他内容，包括密钥和读者自己加的字段；原子写入；文件原本不存在时创建它。文件已有内容不合法时，返回错误并保持原文件不动。
- 任何接口都不返回密钥、本机路径和可执行文件的位置。

`authenticated` 保持 `null`。这一轮不做“检查登录”，不为此调用模型。

### 3. 论文列表

实现 `GET /api/papers`，返回 `{"papers": [...]}`，每一项有 `paper`、`title`、`authors`、`source`、`explanations`、`last_read`，最近读过的在前，没读过的排在后面。

- 只列 `PAPERREAD_HOME/papers` 下的论文。
- 某一篇的缓存损坏时跳过它，其余照常返回。
- `source` 的取值和元数据接口一致（`ar5iv` 对外是 `arxiv_html`）。

### 4. 提问随讲解保存

由读者提问触发的讲解，在讲解对象里加 `asked` 字段：`{"quote", "question", "where", "page"}`，没有的项为 `null`；不是提问触发的讲解，`asked` 为 `null`。

- 导读之前的提问是先存下来、下一次“继续”时回答的。这种情况下，`asked` 记在回答它的那一份讲解上，不记在导读上。
- `asked` 由服务填写，不来自模型输出，模型看不到也改不了这个字段的结构要求。
- 旧的讲解对象没有这个字段，读取时按 `null` 处理，不需要迁移已有数据。

### 5. 上传本地 PDF

实现 `POST /api/papers/upload`。这一项优先级最低；前四项做完、测试通过后再做。

- 请求体是 PDF 文件本身，`Content-Type: application/pdf`。其他类型返回 400。
- 检查文件头是 `%PDF-`。设一个大小上限（建议 50 MB），超过时返回 413。现有的 1 MiB 请求体上限只对这个路径放宽。
- 边收边写到临时文件，不把整个文件读进内存。
- 导入方式和现有的本地 PDF 相同，返回和 `POST /api/papers` 相同的元数据。
- 可选的文件名放在请求头里（建议 `X-Paper-Name`，百分号编码），只用来生成论文标识；不保存读者本机的路径。

顺带请看一个现有行为：本地 PDF 的元数据里，`source_url` 现在是 `file://` 开头的本机路径，会经接口返回给页面。请判断是否改成 `null`；改的话告诉 Claude，页面不依赖这个值。

下面三点不影响这一轮验收，留给后面处理：

1. **换了端口之后再双击。** 默认端口被别的程序占用时，服务会换一个空闲端口。这时再双击 `start.command`，它只检查默认端口，找不到正在运行的服务，接着因为数据目录的锁启动失败，提示“请检查同一数据目录是否已有服务运行”，不会打开页面。建议把实际端口记在锁文件旁边，第二次双击时读出来并打开那个地址。
2. **请求头这一层的报错是英文。** 例如上传非 PDF 时的 `A PDF file is required.`、超限时的 `The request is too large.`。这些会经页面显示给读者。页面已经对上传的 400 和 413 换成中文；其他路径建议后端直接给中文。
3. **排队的问题不在接口里。** 导读之前提的问题存在 `pending` 里，回答之前刷新页面，页面拿不到它，“你的问题”卡片会暂时不见。可以考虑在历史接口或论文元数据里带上尚未回答的 `pending`。
