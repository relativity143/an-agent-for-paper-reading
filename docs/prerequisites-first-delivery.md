# 先说明本文基础，再由读者选择

2026-11-15。按读者要求调整独立 Agent 的开场：陌生领域的读者未必知道该填写什么背景，先由 Agent 说明本文所需的基础，再请读者自评。

## 实际流程

1. 打开论文后，点击“先看看需要哪些基础”。可先切换模型；此时不要求填写背景，不自动调用模型。
2. Agent 依据论文列出 1–8 项必要基础。每项包括名称、浅显的“是什么”、在本文的用途、对应原文位置。先帮助读者认识这些词，不展开论文推导，也不声称读者已经学过。
3. 读者逐项选“已经会／需要补／不确定”，可一键选择都从基础讲起，也可以补充本次目标。首次和重新打开页面时均不预选。
4. 确认选择后，更新本篇概念记录。清单以外的旧记录仍单独交给读者确认或修改；清理这些旧条目不会清掉刚确认的选择。全部确认后，读者点击“继续”或“提问”，开始已有的导读和逐点讲解流程。

保存选择失败或版本冲突，不解锁后续讲解。基础清单可以复用，读者选择每次重新询问；展示清单本身不写入“讲过”“掌握”或阅读日志。读者明确自评“已经会”才记为 `known`；“需要补”和“不确定”都记为 `unsure`，通过备注区分。新条目没有伪造的讲解出处，已有条目保留原出处。

## 后端与对接

- `GET /api/papers/<paper>/prerequisites`：`{paper,ready,items}`。尚未分析或原文变化时 `ready:false,items:[]`；不调用模型。
- `POST` 同一路径：只接受 `{}`，返回 202 `{task}`。沿用 SSE、停止、设置、并发上限和 high effort。没有 `reading_context`、`reading_session`、`record_version` 输入。
- SSE `result` 是基础清单对象，不是讲解卡片，不发显示回执。每项 `{name,description,why,where}`；`where` 复用原文定位对象。HTML ID 必须存在；PDF 页码须在抽取页数内，并提供非空摘录。
- 结果保存在本篇 `prerequisites.json`。指纹覆盖解析后的原文和 PDF 原件；任务开始时重读原文，生成后再次比对。有效缓存可跨重启复用；损坏缓存先报错，显式重新分析成功后再原子替换。失败、取消不写半成品。
- 分析只提供本篇标题、正文、来源和定位，不读取全局档案、本篇概念记录、旧讲解、日志或地图。
- 正常 `explain` 仍要求本次 `reading_context` 和当前 `record_version`；网页把选择组成本页背景，生成新会话编号。外部调用方已有的显式背景接口保持不变。

前端需要新版后端的基础清单接口；缺失接口时提示升级，不回退成凭空填写背景。更新代码后重启正在运行的阅读服务并刷新页面。无需迁移已有数据。

主要实现：`server/prerequisites.py`（纯提示与校验）、`server/service.py`（任务与缓存）、`server/http.py`（路由）、`web/js/reading-context.js`（清单与选择）、`web/js/record.js`（选择与旧记录合并），以及原 `api.js/app.js` 集成。后续 Claude 修改页面时，应保留“先有本文清单、再明确选择、保存成功后才能讲解”的顺序。

## 验证边界

使用合成论文和假模型验证服务、HTTP/SSE 与浏览器交互，不读取真实读者档案，不调用收费模型。新增服务测试覆盖不读取学习状态、缓存与原文变化、排队期间刷新、取消、损坏和写入失败、并发、输入限额及原有讲解门槛。具体通过项数见 [验证记录](validation.md)。

校验能确认数据结构、HTML ID 和 PDF 页码范围，不能自动证明选出的基础完整、解释物理正确，或 PDF 摘录确实逐字出自指定页。对真实论文的选项质量仍需要后续使用反馈；本次不作学习效果结论。现有 PDF 文本抽取和全文长度上限保持不变。
